## Timeline and guidance

- 00:00–02:11: The host introduces the event, prize pool, Atumera pages, and Notion participant pack.
- 02:18–05:58: Livepeer is explained as a decentralized compute network with many GPU servers. Livepeer Agent provides one interface for multimodal capabilities instead of requiring a separate endpoint for each media type. The host emphasizes cheap image, video, and video-with-audio workloads.
- 06:00–07:59: Track 1 is an application built around Livepeer Agent. The experience may be any useful media workflow.
- 08:05–11:22: Track 2 combines Livepeer Agent with OriginTrail DKG. The host highlights compact transferable knowledge, iterative improvement without sending all sensitive prompts to a centralized server, provenance, and collaboration through shared Knowledge Assets.
- 09:39–11:22: Three exposure levels are described: local Edge Node storage, peer-to-peer exchange, and blockchain-anchored Knowledge Assets. The team can choose the level that best serves the use case.
- 12:12–14:06: The reference application is introduced. A user creates a project with a brief, output type, duration, target score, and criteria, then starts a generation.
- 14:32–15:46: A grader agent evaluates each Try and writes memory. On later attempts, the creator/director agent reads that memory and creates a stronger prompt even when the user adds no new instruction.
- 15:48–17:02: The demo shows visible differences across attempts and uses a score from the grader. The lesson for OpenCinema is to show the changed prompt and retrieved knowledge, not just the score.
- 17:18–19:43: The host describes additional output examples and the privacy/collaboration use case: agents can operate over shared Knowledge Assets without exchanging all sensitive information, and provenance records who changed what.
- 19:47–20:11: Closing guidance encourages participants to combine the two primitives into useful products.

## Practical takeaways

1. Make the media result visible and let the audience follow the attempt loop.
2. Show the memory asset and how it changes the next prompt before the next render.
3. Keep private information out of shared assets; share compact lessons rather than raw prompts.
4. Treat the reference application as a starting point, not a required product shape.
